## Purpose

规定 CampusClaw 使用 PostgreSQL 持久化运行的配置、初始化、数据保留与迁移行为。在替换数据库的同时，确保现有学生和教师功能、接口契约、权限边界以及历史业务数据保持兼容。

## ADDED Requirements

### Requirement: PostgreSQL 运行配置

系统 MUST 通过 `CAMPUSCLAW_DATABASE_URL` 配置 PostgreSQL 连接，正常运行不再依赖 SQLite 文件。缺少有效配置、配置为非 PostgreSQL 数据库或启动时连接失败时，系统 MUST 明确报告启动失败，不得静默回退到 SQLite；错误输出 MUST NOT 暴露连接密码。

#### Scenario: 指定 PostgreSQL 连接启动
- **WHEN** 运维提供有效的 PostgreSQL 连接配置并启动服务
- **THEN** 业务读写持久化到指定数据库，且不创建或修改 SQLite 数据文件

#### Scenario: 数据库配置错误
- **WHEN** 连接配置缺失、无效、指向 SQLite 或数据库不可达
- **THEN** 服务启动失败并输出不包含凭据的错误信息，不使用其他数据库继续运行

### Requirement: 初始化与持续保存

系统 SHALL 保留首次启动自动建表及空库装载既有演示数据的行为。已初始化或已迁入有效数据的数据库 MUST NOT 被重新填充或覆盖。服务及数据库容器重建后，已提交数据 MUST 保留。

#### Scenario: 新数据库首次启动
- **WHEN** 服务连接一个空的 PostgreSQL 数据库并完成启动
- **THEN** 现有业务表和原有种子数据可用，演示账号及其业务内容保持不变

#### Scenario: 重启已使用的系统
- **WHEN** 用户已创建业务记录，随后使用原持久化卷重建数据库及后端容器
- **THEN** 原记录完整保留，启动不重复插入种子数据

### Requirement: 存量数据完整迁移

系统 SHALL 提供显式执行的 SQLite 到空 PostgreSQL 目标库的迁移方式，覆盖全部业务表，保留记录标识、外键关系、时间值、枚举含义、布尔值、空值及 JSON（JavaScript Object Notation，JavaScript 对象表示法）内容。迁移 MUST 只读源数据库，并在提交前校验各表记录数量、主键集合与逐字段语义一致性。非空目标或校验失败 MUST 导致迁移失败；失败 MUST NOT 留下部分导入的业务记录。

#### Scenario: 完整迁移历史记录
- **WHEN** 管理员停止源库写入，使用一致的 SQLite 快照迁移到空目标库
- **THEN** 所有业务记录及关联完整保留，迁移报告给出各表数量和校验结果，源库保持不变
- **AND** 服务在迁入后的数据库启动时不以演示数据覆盖历史记录

#### Scenario: 目标已有数据
- **WHEN** 目标任一业务表已有记录，包括先前成功迁入或自动装载的种子数据
- **THEN** 迁移拒绝执行，不覆盖、追加或清空目标记录

#### Scenario: 迁移中途出错
- **WHEN** 迁移因非法值、外键不一致、写入错误或内容校验不一致而失败
- **THEN** 本次目标业务数据写入全部回滚，源库保持不变，并给出不含敏感业务正文和凭据的错误定位

### Requirement: 数据库替换保持业务契约

对相同逻辑数据与操作，系统 MUST 保持原有接口路径、请求和响应结构、状态码、过滤及已定义排序语义、认证与角色权限、跨班返回 404 的隔离规则。系统 MUST 保持讲义与检索、助手配置、对话及 SSE（Server-Sent Events，服务器发送事件）、异步批改和滞留任务恢复、错题、审计、关怀隐私与学情统计的既有行为；前端页面和操作流程 MUST 保持不变。

#### Scenario: 既有功能回归
- **WHEN** 以既有演示数据在 PostgreSQL 上执行当前全部业务测试及主要页面流程
- **THEN** 接口结果和页面行为满足原有断言，OpenAPI 描述及前端生成类型与迁移前一致

#### Scenario: 权限与数据隔离
- **WHEN** 用户尝试读取他班资源、学生调用教师操作或读取他人的关怀记录
- **THEN** 系统保持原有拒绝访问行为，不泄露数据或资源存在性

#### Scenario: 后台批改与重启恢复
- **WHEN** 学生提交作业，或服务重启时存在符合原有重试条件的滞留批改
- **THEN** 后台任务可读取已提交记录并持久化状态、评分、错题和审计，状态机及恢复条件不变

#### Scenario: 类型和排序兼容
- **WHEN** 系统读取中文学科、角色列表、历史日期、空值及嵌套 JSON 数据
- **THEN** 返回字段值、日期序列化及已定义的列表顺序与原有行为一致，不因数据库类型和排序规则变化而改变

### Requirement: 部署入口兼容

Docker Compose 部署 SHALL 提供有持久化存储的 PostgreSQL，且后端 SHALL 在数据库就绪后启动。前端对外端口、同源 `/api` 代理和 `/health` 成功响应 MUST 保持不变。

#### Scenario: 启动完整服务
- **WHEN** 运维按文档完成数据库配置并启动 Docker Compose
- **THEN** 数据库就绪后后端完成初始化，前端通过原有地址和代理访问服务，健康检查仍返回 `{"status":"ok"}`
