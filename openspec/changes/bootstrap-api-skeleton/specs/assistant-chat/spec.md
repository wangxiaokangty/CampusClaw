## Purpose

学生与学科助手的对话能力。回答须基于本班知识库并标注来源，且对话过程对学生可见——助手先做了什么检索、路由到了哪个技能、调用了什么工具，都以执行过程的形式呈现，而不是一个黑盒结果。

## ADDED Requirements

### Requirement: 会话的获取与创建

系统 SHALL 为每个「用户 + 助手」组合维护一个会话。请求创建会话时若该组合已有会话，MUST 返回既有会话而非新建。

#### Scenario: 首次进入某学科助手
- **WHEN** 学生请求与某助手的会话且此前无会话
- **THEN** 系统创建会话并返回其标识，消息列表为空

#### Scenario: 再次进入同一助手
- **WHEN** 学生再次请求与同一助手的会话
- **THEN** 系统返回此前的会话标识与全部历史消息

#### Scenario: 请求他班助手的会话
- **WHEN** 学生请求与其他班级助手的会话
- **THEN** 系统返回 404

### Requirement: 会话历史读取

系统 SHALL 提供端点返回指定会话的消息列表，按时间升序。每条助手消息 MUST 保留其技能标识、来源引用与执行过程记录。

#### Scenario: 读取历史
- **WHEN** 学生请求某会话的消息
- **THEN** 系统按时间升序返回全部消息
- **AND** 助手消息包含当时的来源引用与执行过程

#### Scenario: 读取他人会话
- **WHEN** 用户请求不属于自己的会话
- **THEN** 系统返回 404

### Requirement: 流式发送消息

发送消息的端点 SHALL 以服务器推送事件流响应，事件类型包括：执行过程步骤、回答文本增量、结束标记。

结束事件 MUST 携带最终消息标识、来源引用列表、token 用量与耗时。

#### Scenario: 发送提问并接收流式回答
- **WHEN** 学生发送一条提问
- **THEN** 系统先推送若干执行过程步骤事件
- **AND** 随后推送多个回答文本增量事件
- **AND** 最后推送结束事件，含消息标识与来源引用
- **AND** 用户消息与完整的助手消息均已持久化

#### Scenario: 客户端中途断开
- **WHEN** 客户端在流式响应完成前断开连接
- **THEN** 系统停止推送
- **AND** 已生成的内容不产生半条损坏的持久化消息

### Requirement: 执行过程可见

助手消息 MUST 记录其执行过程，至少包含：理解问题意图、检索班级知识库（含命中片段数与命中的讲义位置）、路由到的技能、组织生成回答。若调用了 MCP 工具，MUST 额外记录所调用的工具与其所属服务器。

#### Scenario: 检索命中时的执行过程
- **WHEN** 学生的提问在知识库中有命中
- **THEN** 执行过程中的检索步骤标明命中片段数与具体的讲义标题与位置

#### Scenario: 调用工具时的执行过程
- **WHEN** 助手在回答过程中调用了某个 MCP 工具
- **THEN** 执行过程中出现该工具调用步骤，标明工具名与来源服务器

### Requirement: 回答须有来源依据

助手回答 MUST 基于检索到的知识块，并在消息中附带来源引用（讲义标题与位置）。

当知识库中无相关内容时，助手 MUST 明确告知未检索到相关资料并建议补充条件或请教师上传讲义，MUST NOT 凭空给出结论。

#### Scenario: 有命中时标注来源
- **WHEN** 学生提问且知识库有命中
- **THEN** 助手消息附带来源引用，每条含讲义标题与位置标识

#### Scenario: 无命中时拒绝臆测
- **WHEN** 学生提问且知识库无任何相关内容
- **THEN** 助手回答说明未检索到相关资料
- **AND** 来源引用列表为空
- **AND** 回答中不包含对该问题的实质性结论

### Requirement: 解题引导技能改变回答形态

当「解题引导」技能处于启用状态且学生的输入被判定为题目类提问时，助手 MUST 以引导思路的形式回应——回顾相关知识、提示可考察的关键量、邀请学生给出第一步推导——而 MUST NOT 直接给出最终答案。

该技能停用时，助手直接讲解。

#### Scenario: 技能启用时提问题目
- **WHEN** 「解题引导」启用，学生提交一个题目类提问
- **THEN** 助手回答为引导式，不含最终答案
- **AND** 消息的技能标识为解题引导

#### Scenario: 技能停用时提问题目
- **WHEN** 「解题引导」停用，学生提交同样的提问
- **THEN** 助手直接讲解相关知识点
- **AND** 消息的技能标识为空或标记为直接问答

### Requirement: 对话写入审计

每次助手响应完成后，系统 MUST 写入一条审计记录，含时间、用户、班级、技能标识、动作描述、参数摘要、结果状态、耗时与 token 用量。

#### Scenario: 对话产生审计记录
- **WHEN** 一次对话流式响应正常结束
- **THEN** 审计日志中新增一条对应记录，可在审计查询中检索到
