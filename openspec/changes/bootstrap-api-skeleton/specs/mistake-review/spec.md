## Purpose

学生的错题本与按错因的针对性讲解。错题来自作业批改中被判错的提交，讲解沿用与对话一致的原则——引导为主、依据讲义、默认不直接给最终答案。

## ADDED Requirements

### Requirement: 学生查看自己的错题

系统 SHALL 提供端点返回当前学生的错题列表，每条含来源作业标题、题目、学生原作答与错因说明。

学生 MUST NOT 能读取其他学生的错题。

#### Scenario: 读取错题列表
- **WHEN** 学生请求自己的错题列表
- **THEN** 系统返回其全部错题，含题目、原作答与错因

#### Scenario: 无错题
- **WHEN** 学生尚无任何错题
- **THEN** 系统返回空列表，状态为成功

#### Scenario: 读取他人错题
- **WHEN** 学生请求指定其他学生标识的错题
- **THEN** 系统忽略该参数仅返回自己的错题，或返回 403

### Requirement: 错题讲解

学生 SHALL 能对某条错题请求讲解。系统 MUST 基于该错题的错因与本班知识库生成讲解，并附带来源引用。

当「错题讲解」技能配置为引导模式时，讲解 MUST NOT 直接给出最终答案，而是针对错因说明思路偏差所在。

讲解结果 MUST 持久化到该错题记录上，重复请求时返回既有讲解而非重复生成。

#### Scenario: 首次请求讲解
- **WHEN** 学生对一条尚无讲解的错题请求讲解
- **THEN** 系统生成讲解并附带讲义来源引用
- **AND** 讲解被保存到该错题记录

#### Scenario: 重复请求讲解
- **WHEN** 学生对已有讲解的错题再次请求
- **THEN** 系统返回既有讲解
- **AND** 不重复计入 token 用量

#### Scenario: 对他人错题请求讲解
- **WHEN** 学生对不属于自己的错题标识请求讲解
- **THEN** 系统返回 404

### Requirement: 错题讲解写入审计

每次实际生成讲解时，系统 MUST 写入一条审计记录，含学生、班级、错题讲解技能标识、错题标识、结果状态、耗时与 token 用量。

#### Scenario: 生成讲解产生审计
- **WHEN** 系统为一条错题生成了新的讲解
- **THEN** 审计日志中新增对应记录
