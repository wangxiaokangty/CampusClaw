## Purpose

定义用户身份的确立方式与班级数据边界。系统中每个用户属于且仅属于一个班级，所有班级范围内的数据对其他班级不可见——本能力规定这条边界如何被强制，以及越界访问时系统如何响应。

## ADDED Requirements

### Requirement: 账号列表可公开读取

登录界面需要展示可选身份。系统 SHALL 提供无需认证的账号列表端点，返回每个账号的标识、姓名、角色、班级与头像。

该端点 MUST NOT 返回任何凭据相关字段。

#### Scenario: 未认证获取账号列表
- **WHEN** 客户端在无 Authorization 头的情况下请求账号列表
- **THEN** 系统返回全部账号的标识、姓名、角色、班级名称与头像
- **AND** 响应中不包含任何令牌、密钥或密码字段

### Requirement: 选人登录签发访问令牌

系统 SHALL 接受一个账号标识并签发 JWT Bearer 令牌，令牌载荷包含用户标识、角色与班级标识。

此登录方式为演示用途，MUST 在接口文档中显式标注其不适用于生产环境。

#### Scenario: 以有效账号登录
- **WHEN** 客户端提交一个存在的账号标识
- **THEN** 系统返回访问令牌与该用户的完整信息（含角色、班级）

#### Scenario: 以不存在的账号登录
- **WHEN** 客户端提交一个不存在的账号标识
- **THEN** 系统返回 401
- **AND** 不签发任何令牌

### Requirement: 当前用户上下文

系统 SHALL 提供端点返回当前令牌对应的用户、其所属班级，以及该班级下已开设的学科列表。

#### Scenario: 携带有效令牌请求
- **WHEN** 客户端携带有效令牌请求当前用户
- **THEN** 系统返回用户信息、班级信息与该班级的学科列表

#### Scenario: 令牌缺失或无效
- **WHEN** 客户端未携带令牌，或携带已过期、被篡改的令牌
- **THEN** 系统返回 401

### Requirement: 班级数据边界

所有承载班级范围数据的端点 MUST 将结果限制在请求者所属班级内。跨班级访问 MUST 返回 404 而非 403。

返回 404 是为了不泄漏其他班级中资源的存在性。

#### Scenario: 读取本班资源
- **WHEN** 用户请求属于自己班级的资源
- **THEN** 系统正常返回该资源

#### Scenario: 读取他班资源
- **WHEN** 用户请求一个确实存在但属于其他班级的资源标识
- **THEN** 系统返回 404
- **AND** 响应体不透露该资源是否存在

#### Scenario: 列表端点的班级过滤
- **WHEN** 用户请求任一班级范围内的列表端点
- **THEN** 返回结果中不包含任何其他班级的数据，无论查询参数如何组合

### Requirement: 角色权限区分

教师专属操作 MUST 拒绝学生身份的调用。教师专属操作包括：讲义上传与删除、助手配置的任何修改、作业发布、教师改分、审计日志查询。

#### Scenario: 学生尝试修改助手配置
- **WHEN** 学生身份的用户请求修改助手提示词、技能或 MCP 服务器
- **THEN** 系统返回 403
- **AND** 配置保持不变

#### Scenario: 学生读取助手配置
- **WHEN** 学生身份的用户请求查看本班助手配置
- **THEN** 系统返回配置内容（只读）
- **AND** 响应中不包含 API Key 明文
